hestia

GitHub: https://github.com/aquaxis/hestia

Overview

Hestia — Hardware Engineering Stack for Tool Integration and Automation — is an AI-driven hardware development environment that integrates FPGA, ASIC, PCB, HAL, and embedded software development tools. Nine Conductors (domain-specialized AI agents) collaborate via agent-cli IPC to enable automatic design generation from specifications, unified orchestration of vendor tools, and reproducible container-based builds.

Features

  • 9 Conductor architecture — domain-specialized AI agents for RTL, FPGA, ASIC, PCB, HAL, Apps, Debug, and RAG
  • Unified IPC — all inter-Conductor communication uses agent-cli-compatible messaging (`agent-cli send `)
  • Specification-driven development — HDL code, constraint files, and testbenches are dynamically generated by LLMs from natural-language specifications
  • Vendor-agnostic abstraction — unified interface via `ToolAdapter`/`VendorAdapter` traits; add tools by writing an `adapter.toml`
  • Engine switching — peer-driven engine (`agent_cli`) or a Claude Code wrapper (`claude_cli_shim`) selected via `[engine] type`
  • Container and local execution — Podman-based or local build environments for reproducible results

Installation



git clone https://github.com/aquaxis/hestia.git

cd hestia

./install.sh

The installer checks prerequisites, builds the workspace, and prepares the `.hestia/` project directory and `.github/` CI definitions. A sample instruction file is provided as `sample_instructions.md`.

Usage

Hestia works per project: initialize `.hestia/`, write a natural-language specification (see `sample_instructions.md`), and let the Conductors plan, generate HDL/constraints/testbenches, and drive vendor toolchains. Configuration, the Conductor roster, and engine selection are managed in the `.hestia/` configuration files. See the repository's `README.md` and `WORKFLOWS.md` for the full development workflow, and the `FAQ.md` for common questions.
