rv_saturn

GitHub: https://github.com/aquaxis/rv_saturn

Overview

RISC-V Saturn is a multicore RISC-V soft core plus the surrounding SoC, debug, and FPGA implementation set. The core implements RV32I with the RVV vector extension (Zve32x subset), and the SoC uses a dual-heart multicore configuration — the name comes from Saturn: the target application sits at the center, with RISC-V cores around it like the rocks of its rings.

Features

  • RV32I + RVV Zve32x (VLEN=128, ELEN=32, SEW 8/16/32, LMUL 1/8–8, masked operations, unit-stride loads/stores); element-serial vector execution; M and A extensions not implemented by design
  • Single-stage core with fixed 32-bit instructions; unimplemented instructions do not trap (compile with `-march` restricted to the implemented range)
  • Dual-heart multicore: each heart owns private IMEM/DMEM, sharing only the peripheral bus; round-robin system bus arbitration; hardware mutex (`apb_mutex`, lock + mailbox) for inter-heart synchronization since there is no A extension; `CORES=2` default, `CORES=1` for single core
  • APB peripherals (base `0x8000_0000`): UART with GPIO, QSPI, I2C, timer, PLIC interrupt controller, and the mutex
  • Debug: RISC-V Debug Module / DTM; Verilator RTL simulation; OpenOCD JTAG debugging (including a Verilator+OpenOCD simulation environment)
  • Target FPGA: AMD (Xilinx) Artix-7 (Arty A7); xsim flow available alongside Verilator
  • Performance (33.33 MHz, no `-O`): Dhrystone 22.059 DMIPS (0.662 DMIPS/MHz), CoreMark 0.366 CoreMark/MHz

Installation

A RISC-V toolchain (`riscv32i`, overridable on the command line) is required for the bundled applications; Vivado is needed for FPGA builds. Clone the repository, then build apps and simulations with make:



make -C apps/ <app>                 # build an application

make -C apps/ binary                # generate hex

make -C sim sim_fpga_verilator SCENARIO=<app>   # Verilator RTL simulation

make -C sim sim_fpga SCENARIO=<app>             # xsim simulation (needs Vivado)

Usage

Applications under `apps/` include `gpio`, `gpio_loop`, `uart`, `coremark`, `dhrystone`, a bootloader, the self-checking ISA/vector test `test_inst`, and the dual-heart/mutex test `mc_test`. A normal Verilator run ends with `[SIM] PASS`. For FPGA, build the `artya7` target and select the application to embed with `SCENARIO=` (default `gpio_loop`):



make -C fpga artya7 SCENARIO=<app>

Each subdirectory (`rtl/`, `sim/`, `simocd/`, `fpga/`, `apps/`) carries its own README with details.
