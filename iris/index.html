iris

GitHub: https://github.com/aquaxis/iris

Overview

IRIS (Immutable RTL, Intentional Semantics) is a hardware description language for combinational and sequential circuits, designed to be readable and writable by both humans and AI. It takes Rust's design philosophy to hardware: against SystemVerilog's roughly 220 reserved words, IRIS provides the expressiveness RTL design needs with 58 keywords.

Features

  • Safety first — no implicit type conversion; bit-width mismatches are compile errors
  • Explicit over implicit — intent is expressed clearly in code; unified assignment operators (`=` for blocking, `<=` for non-blocking) and `{}` notation
  • FSM description with states, transitions (`goto`), and output encoding
  • Combinational (`comb`) and synchronous (`sync`) blocks; `mem` declarations for RAM/ROM; `interface`, `enum`, `struct`, `union`, and packages
  • Simulation in interpreter or compiler mode (the compiled binary runs an order of magnitude faster); VCD output with array dumping
  • Transpilers both ways — IRIS↔SystemVerilog and IRIS↔Veryl — with diagnostics instead of silent drops
  • Formal equivalence verification: all example designs are formally proven equivalent to their SystemVerilog conversion
  • Tooling: formatter, linter, Language Server with a VSCode extension, and a browser block-diagram viewer

Installation

IRIS is built from source with a Rust toolchain; Node.js is needed only for the browser viewer and the VSCode extension build.



# Simulator

cd sim/iris-sim

cargo build --release



# Command-line tools (transpilers, formatter, LSP, unified frontend)

cargo build --release --manifest-path tools/iris-rs/Cargo.toml

cargo build --release --manifest-path tools/iris2sv-rs/Cargo.toml

cargo build --release --manifest-path tools/sv2iris-rs/Cargo.toml

cargo build --release --manifest-path tools/irisfmt-rs/Cargo.toml

cargo build --release --manifest-path tools/irisfmt-lsp-rs/Cargo.toml

Usage

The unified frontend `iris` dispatches each tool as a subcommand:



iris sim -i design.iris -o out.vcd -c 100      # simulate (interpreter)

iris compile -i design.iris -o sim --release   # compile to a native simulator

iris sv design.iris                            # convert IRIS to SystemVerilog

iris from-sv design.sv                         # convert SystemVerilog to IRIS

iris fmt design.iris                           # format

iris lint design.iris                          # style check

iris lsp                                       # Language Server

iris formal -i design.iris -o out/             # produce a reference model for formal verification

iris schematic                                 # browser block-diagram viewer (npm dev server)

Example designs (async FIFO, RV32I processor, counter, ALU, decoder, register file) run identically in interpreter, compiler, and Verilator modes. The complete 21-chapter language specification is in `spec/iris_spec.md`; comparison documents for SystemVerilog and Veryl are in `doc/`.
