ChronoMark

GitHub: https://github.com/aquaxis/ChronoMark

Overview

ChronoMark manages tasks in Markdown and displays them as a Gantt chart. One task is one Markdown file (`.md`) — editable as text, versioned with Git, and viewable/manipulable as a Gantt chart in the browser. The name combines **Chrono** (time) and **Markdown**.

Features

  • Markdown is the single source of truth — 1 task = 1 file, no database; history and diffs are Git's job
  • Gantt chart using the bundled jQueryGantt: dependencies, hierarchy, progress, and milestones editable inline, with autosave (no save button)
  • Two editing modes: a per-item property form (with Obsidian-style live Markdown preview) and raw `.md` editing with server-side YAML/schema validation
  • Hierarchy is the directory structure; references always use immutable ULID uids (renames/moves never break dependencies)
  • Optimistic locking — concurrent external edits are detected and rejected with `409` instead of overwriting
  • Multiple projects with an "All projects" combined view; live updates via WebSocket file-change detection
  • Import from external tools: jQueryGantt export / Lychee Redmine / GitHub Projects v2 / Backlog normalized to a `UnifiedTask` schema

Installation



./setup.sh    # checks Node >= 20, installs dependencies, generates the CodeMirror 6 bundle

npm start     # serves http://localhost:4000 (data in ./data)

`npm install` alone can also start it. A `demo` project is auto-created on first open.

Usage



npm run project:create -- <name>       # create a project (no server restart needed)

npm run sample:create                  # sample and website sample projects

npm run import:gantt -- <project>      # import a jQueryGantt export JSON

npm run dev                            # auto-reload development server

In the browser: **Explorer** (task tree), task edit (form or `.md` mode), and the Gantt view (drag bars, connect dependencies, milestones, resource view, status filters). A `PORT=4123 CHRONOMARK_DATA=/path/to/data npm start` form changes the port and data directory. Screenshots and details are in the repository's `doc/` directory.
